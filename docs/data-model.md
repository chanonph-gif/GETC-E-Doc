# โครงสร้างข้อมูลตั้งต้น

เอกสารนี้เป็นแบบข้อมูลเชิงแนวคิดสำหรับ ED-02 รายละเอียด schema และชื่อฟิลด์จริงกำหนดเมื่อเลือกเทคโนโลยี โดยต้องรักษาความสัมพันธ์และข้อบังคับด้านล่าง

## หน่วยข้อมูลและความสัมพันธ์

| หน่วยข้อมูล | ความสัมพันธ์และข้อมูลสำคัญ |
| --- | --- |
| กอง | เจ้าของทะเบียน สมาชิก แฟ้มเรื่อง และขอบเขตข้อมูล |
| ผู้ใช้และสมาชิก | ผู้ใช้หนึ่งคนมีสังกัดจริงและเป็นสมาชิกกองได้หลายบทบาท มีวันเริ่ม สิ้นสุด และช่วงรักษาการ |
| หนังสือ | เก็บทิศทางรับหรือส่ง ชนิด เรื่อง เลขต้นทาง วันที่ ผู้เกี่ยวข้อง และระดับการเข้าถึง |
| แหล่งอ้างอิง | หนังสือหนึ่งฉบับอ้างอิงระบบเดิมได้ เก็บระบบ รหัสรายการ เลขที่แสดง และ URL แยกกัน |
| รายการทะเบียน | ผูกหนังสือ กอง ชุดเลข รอบปี เลขลำดับ และผู้ลงทะเบียน คงรายการยกเลิก |
| เรื่องงาน | มีเจ้าของหลัก สถานะ เป้าหมาย และหมวดงาน หนังสือเชื่อมได้หลายเรื่องผ่านรายการความสัมพันธ์ |
| งานย่อย | อยู่ภายใต้เรื่องงาน มีผู้รับผิดชอบ ผู้ตรวจ กำหนด ผลงาน และงานแม่เมื่อจำเป็น |
| รุ่นเอกสารและไฟล์ | รุ่นอ้างอิงไฟล์ เก็บขนาด ชนิด ค่าตรวจสอบ ผู้แนบ และบทบาทร่างหรือฉบับส่งจริง |
| รอบส่งตรวจ | อ้างอิงผู้ส่ง ผู้ตรวจ และรุ่นผลงานที่แน่นอน เก็บคำตรวจและผลแต่ละรอบ |
| ผู้รับและการส่ง | หนังสือมีผู้รับหลายราย การส่งหนึ่งครั้งเก็บผลต่อผู้รับ ส่งซ้ำเป็นเหตุการณ์ใหม่ |
| การตอบรับและรับทราบ | แยกตอบรับการจัดส่งออกจากรับทราบภายใน เก็บผู้ทำ เวลา และหลักฐาน |
| สิทธิ์และประวัติ | ผูกสิทธิ์กับกอง เรื่อง หนังสือ และไฟล์ เก็บผู้ให้สิทธิ์และเหตุการณ์เปลี่ยนแปลง |

## ข้อบังคับที่ฐานข้อมูลและบริการต้องรักษา

- รหัสภายในข้อมูลไม่ใช้แทนเลขที่แสดงบนทะเบียนหรือหนังสือ
- เลขลำดับไม่ซ้ำภายในกอง ชุดทะเบียน และรอบปี มีข้อบังคับที่ฐานข้อมูลรองรับการแข่งขันของคำขอ
- ยืนยันลงทะเบียนและออกเลขในธุรกรรมเดียวกัน คำขอซ้ำต้องคืนรายการเดิม
- การลงทะเบียนจริงเก็บเวลาอัตโนมัติแยกจากวันรับจริงและวันที่บนหนังสือ การแสดงปี พ.ศ. แยกจากข้อมูล timestamp
- ชุดเลขและรอบปีมีเวอร์ชันการตั้งค่า ไม่เปลี่ยนเลขเก่าตามค่าตั้งใหม่
- หนังสือที่คล้ายกันต้องเตือนให้ตรวจ ไม่ปฏิเสธด้วยเลขต้นทางเพียงช่องเดียว เพราะเอกสารเพิ่มเติมและเอกสารไม่มีเลขอาจเกิดขึ้นได้
- เพิ่มหรือยกเลิกความสัมพันธ์ข้ามแฟ้มไม่ขยายสิทธิ์อ่านหนังสือหรือไฟล์ ผู้ใช้เห็นเฉพาะข้อมูลที่อยู่ในขอบเขตสิทธิ์
- ส่งตรวจต้องผูกกับรุ่นเอกสารที่แน่นอน การเพิ่มรุ่นหลังผ่านตรวจต้องเริ่มตรวจรุ่นใหม่
- ฉบับส่งจริงและหลักฐานการส่งคงเดิม การแก้ไขให้เพิ่มรุ่นหรือบันทึกเหตุการณ์ใหม่ตามขั้นตอนองค์กร
- การยุติสมาชิกหรือสิ้นสุดผู้รักษาการต้องทำให้การตรวจสิทธิ์คำขอถัดไปเป็นไปตามขอบเขตใหม่ ประวัติผู้ดำเนินการเดิมยังอยู่
- เรื่องที่ต้องตอบหนังสือปิดได้เมื่อมีฉบับส่งจริงเชื่อมอยู่และงานจำเป็นเสร็จหรือยกเลิกพร้อมเหตุผล

## ส่วนประกอบระบบที่เสนอ

ใช้เว็บแอป บริการฝั่งเซิร์ฟเวอร์ ฐานข้อมูลเชิงสัมพันธ์ และที่เก็บไฟล์แบบ private แยกสภาพแวดล้อมพัฒนา ทดสอบ และใช้งานจริง ตรวจสิทธิ์ก่อนอ่านข้อมูล สร้างตัวนับ ส่งออก หรือดาวน์โหลดไฟล์ทุกครั้ง

เริ่มอ้างอิงระบบเดิมด้วยรหัสและลิงก์ เมื่อมีวิธีเชื่อมที่ยืนยันแล้วจึงเพิ่มตัวเชื่อม โดยใช้รหัสรายการต้นทางป้องกันการนำเข้าซ้ำและมีรายการงานที่เชื่อมไม่สำเร็จให้ตรวจแก้
