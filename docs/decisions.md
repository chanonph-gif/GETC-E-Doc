# ข้อกำหนดตั้งต้นและประเด็นที่ต้องกำหนด

เอกสารนี้เก็บฐานออกแบบและข้อมูลที่ต้องใช้ก่อนพัฒนา การปรับแต่ละรายการให้ระบุผู้ให้ข้อยุติ วันที่ เหตุผล และผลต่องาน ED ที่เกี่ยวข้อง

## ฐานที่ใช้เตรียมโครงการ

| รหัส | ฐานออกแบบ | ผลต่อการพัฒนา |
| --- | --- | --- |
| D01 | เริ่มจากระบบภายในกองเสมือนหนึ่งกอง | ทุกข้อมูลระบุกองเจ้าของ รองรับการขยายโดยไม่ปะปนสิทธิ์ |
| D02 | ใช้เลขติดตามภายในกอง | แยกเลขทางการและการลงนามตามกระบวนการองค์กร |
| D03 | เริ่มด้วยการบันทึกเลขอ้างอิงและลิงก์ระบบเดิม | ส่วนรับและติดตามทำต่อได้ก่อนมีตัวเชื่อมอัตโนมัติ |
| D04 | ค้นข้อมูลทะเบียนในรุ่นแรก | ค้นภายในไฟล์และอ่านเอกสารช่วยกรอกเป็นงานต่อยอด |
| D05 | ใช้เว็บแอปและตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ | ต้องตรวจ API ไฟล์ ค้นหา ตัวนับ รายงาน และส่งออกด้วยสิทธิ์เดียวกัน |
| D06 | ใช้ข้อมูลสมมติใน repository สาธารณะ | หนังสือจริง บัญชี และความลับระบบเก็บในพื้นที่ที่องค์กรกำหนด |

## ข้อมูลที่ต้องใช้ก่อนกำหนดรายละเอียด

| ประเด็น | สถานะ | ผู้ให้ข้อมูล | งานที่ดำเนินการได้ระหว่างนี้ |
| --- | --- | --- | --- |
| ชื่อและรหัสกอง อำนาจออกหนังสือ ผู้ลงนาม | Uncertain | เจ้าของระบบงานและสารบรรณองค์กร | กำหนดตัวอย่างเลขภายในและแบบฟอร์ม |
| เทคโนโลยีและพื้นที่ติดตั้งที่องค์กรอนุญาต | Data unavailable | ผู้ดูแล IT และผู้พัฒนา | ออกแบบข้อมูล ขั้นตอน และต้นแบบ |
| การเข้าใช้ด้วยบัญชีองค์กรหรือวิธีอื่น | Data unavailable | ผู้ดูแลบัญชีและความปลอดภัย | กำหนดบทบาท อายุสมาชิก และขอบเขตสิทธิ์ |
| API หรือวิธีส่งออกจากระบบเดิม | Data unavailable | ผู้ดูแลระบบเดิม | วางช่องรหัสอ้างอิงและลิงก์ |
| จำนวนผู้ใช้ ปริมาณหนังสือ ขนาดไฟล์ | Data unavailable | ผู้ประสานงานกอง | เตรียมแบบประเมินขนาดและกรณีทดสอบ |
| ประเภทเอกสารที่รับเข้า อายุเก็บ และการทำลาย | Data unavailable | เจ้าของข้อมูลและสารบรรณองค์กร | ออกแบบระดับการเข้าถึงและประวัติ |
| รอบปี เลขเริ่มต้น และการลงทะเบียนย้อนหลัง | Uncertain | ผู้ประสานงานและเจ้าของระบบงาน | ทำกติกาออกเลขแบบตั้งค่าได้ |
| เป้าหมายเวลาตอบสนอง สำรอง และกู้คืน | Data unavailable | เจ้าของระบบงานและ IT | กำหนดวิธีวัดและหลักฐานทดสอบ |
| ทีมพัฒนา กำหนดวัน และงบประมาณ | Data unavailable | ผู้รับผิดชอบโครงการ | จัดลำดับงานตามรอบและการพึ่งพา |

## วิธีบันทึกข้อยุติใหม่

เพิ่มรายการพร้อมวันที่ ผู้ให้ข้อยุติ เหตุผล ทางเลือกที่พิจารณา และงาน ED ที่ได้รับผล หากเปลี่ยนพฤติกรรมระบบ ให้แก้ข้อกำหนดกับเกณฑ์ตรวจรับส่วนที่เกี่ยวข้องในชุดเดียวกัน

## แนวทางสำหรับต้นแบบรอบ 0

วันที่ 29 ตุลาคม 2569 ใช้ HTML CSS และ JavaScript modules สำหรับต้นแบบใน prototype/ และ Node.js 22 ขึ้นไปสำหรับเปิดเว็บ ทดสอบ และ build โดยไม่มี dependency ภายนอก ช่วยให้ทดลองรูปแบบข้อมูลกับขั้นตอนก่อนเลือก framework และพื้นที่ติดตั้งระบบจริง

ข้อมูลจำลองอยู่ใน localStorage ไฟล์ตัวอย่างอยู่ใน IndexedDB ของเบราว์เซอร์ ใช้ชุดคำสั่งจำลองผ่าน domain.mjs และเลข DEMO การเลือกบุคคลบนหน้าจอมีไว้ทดลองบทบาท การยืนยันตัวตน การออกเลขในธุรกรรมฐานข้อมูล และการตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ต้องทำในรอบพัฒนาระบบจริง
