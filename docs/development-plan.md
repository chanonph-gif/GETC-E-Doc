# แผนพัฒนาระบบ E Doc สำหรับกองเสมือน

ฉบับ 1.0 วันที่ 29 ตุลาคม 2569

แผนตั้งต้นสำหรับพัฒนา สถานะงานปัจจุบันติดตามใน [Issues](https://github.com/chanonph-gif/GETC-E-Doc/issues) และ [รายการงาน](backlog.md)

พัฒนาระบบภายในกองให้รับเรื่อง มอบหมาย ติดตาม และรวบรวมเอกสารได้ครบวงจร โดยอ้างอิงหนังสือทางการจากระบบเดิม เมื่อเปิดใช้งาน สมาชิกต้องเห็นงานของตน หัวหน้าตามเรื่องค้างได้ และค้นเส้นทางของหนังสือแต่ละเรื่องย้อนหลังได้

## 1 เป้าหมายและขอบเขตรุ่นแรก

| รวมในรุ่นแรก | แนวทางดำเนินการ |
| --- | --- |
| ทะเบียนรับและส่ง | ออกเลขติดตามภายในกอง เก็บเลขหนังสือและเลขอ้างอิงจากระบบเดิมแยกกัน |
| มอบหมายและติดตาม | มีเจ้าของเรื่อง งานย่อย กำหนดส่ง และการส่งกลับแก้ไขหนึ่งระดับ |
| เอกสารและแฟ้มเรื่อง | เก็บร่างและฉบับส่งจริง รวมหนังสือหลายฉบับในเรื่องเดียวกัน |
| ค้นหาและรายงาน | ค้นจากข้อมูลทะเบียน ดูงานค้างและส่งออกทะเบียนตามสิทธิ์ |
| ผู้ใช้และประวัติ | กำหนดสิทธิ์รายเรื่อง เก็บการเปลี่ยนแปลงและเหตุการณ์สำคัญ |
| ความพร้อมใช้งาน | สำรองและกู้คืนข้อมูล มีคู่มือสั้นและผู้ดูแลประจำ |

### ขอบเขตที่พัฒนาภายหลัง

การออกเลขหนังสือทางการในนามกอง การลงนามอิเล็กทรอนิกส์ การเชื่อมระบบเดิมอัตโนมัติ การอ่านเอกสารช่วยกรอก การค้นทั้งเนื้อหาไฟล์ และการย้ายเอกสารย้อนหลังทั้งหมด ให้แยกเป็นงานต่อยอด

### แนวทางที่ใช้เริ่มพัฒนา

ใช้เว็บแอปสำหรับคอมพิวเตอร์และมือถือ เริ่มจากกองเสมือนหนึ่งกอง แต่ข้อมูลทุกชุดต้องระบุกองเจ้าของเพื่อรองรับการขยาย ใช้ข้อมูลตัวอย่างในช่วงพัฒนา และใช้การบันทึกเลขอ้างอิงหรือลิงก์กลับระบบเดิมก่อน

เลขทะเบียนภายในเป็นเลขติดตามงาน ส่วนเลขหนังสือทางการและอำนาจลงนามให้ใช้ตามช่องทางองค์กร การกดเห็นชอบผลงานในระบบนี้เป็นขั้นตอนทำงานภายในกอง

จุดส่งมอบรุ่นแรก: รับหนังสือหนึ่งฉบับ มอบหมายหลายงาน ตรวจผลงาน บันทึกหนังสือตอบ และปิดเรื่อง พร้อมค้นประวัติทั้งหมดได้

## 2 ขั้นตอนทำงานและผู้รับผิดชอบ

### หนังสือเข้า

ผู้ประสานงานลงรับและตรวจข้อมูล หัวหน้าหรือผู้ได้รับมอบหมายคัดแยกเป็นเรื่องเพื่อทราบหรือเรื่องที่ต้องดำเนินการ จากนั้นกำหนดเจ้าของเรื่องและงานย่อย ผู้ปฏิบัติส่งผลงานให้ตรวจ และเจ้าของเรื่องรวบรวมผลก่อนตอบกลับหรือปิดเรื่อง

### หนังสือออกและเรื่องที่กองเริ่มเอง

ผู้ปฏิบัติเปิดเรื่องใหม่หรือเลือกแฟ้มเดิม แนบร่างและส่งตรวจ เมื่อได้ฉบับที่จะใช้ดำเนินการทางการ ให้ส่งเข้าสู่ขั้นตอนตรวจ ลงนาม และออกเลขตามระบบองค์กร แล้วกลับมาบันทึกเลขทางการ ฉบับส่งจริง ผู้รับ และหลักฐานการส่งในระบบกอง

การจดทะเบียนส่ง การส่งจริง และการตอบรับเป็นคนละเหตุการณ์ ต้องเก็บแยกกัน หนังสือที่ส่งแล้วแต่ยังต้องรอผล ให้เรื่องงานคงอยู่ในสถานะรอผลตอบกลับ

| บทบาท | สิทธิ์และหน้าที่หลัก |
| --- | --- |
| เจ้าของระบบงาน<br>[ผู้ได้รับมอบหมาย] | กำหนดกติกา ขอบเขต ผู้เข้าถึงเอกสาร และรับรองผลการทดลองใช้ |
| สารบรรณหรือผู้ประสานงาน | ลงรับ ตรวจรายการซ้ำ จัดทะเบียน ส่งต่อ และบันทึกผลการส่งตามสิทธิ์ |
| หัวหน้ากองหรือผู้แทน | มอบหมาย ปรับกำหนด ตรวจผลงาน ส่งกลับแก้ไข และปิดหรือเปิดเรื่องใหม่ตามสิทธิ์ |
| เจ้าของเรื่องและผู้ปฏิบัติ | รับงาน แนบผลงาน ส่งตรวจ และจัดการงานย่อยในขอบเขตที่ได้รับมอบหมาย |
| ผู้รับเพื่อทราบ | อ่านและรับทราบเฉพาะเรื่องที่ได้รับ ไม่ได้สิทธิ์แก้หนังสือหรือปิดงาน |
| ผู้ดูแลระบบและข้อมูล | จัดการบัญชี การตั้งค่า การสำรอง และการกู้คืน โดยไม่ให้สิทธิ์อ่านเอกสารทั้งหมดโดยอัตโนมัติ |

### เงื่อนไขสำหรับสมาชิกกองเสมือน

เก็บสังกัดจริงแยกจากบทบาทในกอง รองรับสมาชิกหลายบทบาทและช่วงเวลารักษาการ เมื่อย้ายคนหรือสิ้นสุดสมาชิก ให้โอนงานค้างและยุติสิทธิ์เข้าถึง โดยคงชื่อผู้ดำเนินการเดิมไว้ในประวัติ

แต่ละเรื่องมีเจ้าของเรื่องหลักหนึ่งคน ผู้ร่วมงานอาจมีหลายคน การให้สิทธิ์ดูเรื่องต้องพิจารณาสิทธิ์ดูหนังสือและไฟล์ที่อยู่ในเรื่องนั้นด้วย

## 3 ข้อมูลรับหนังสือและเปิดเรื่อง

แบบฟอร์มแบ่งเป็นข้อมูลหนังสือและข้อมูลสั่งงาน เพื่อให้ลงรับได้ก่อนแล้วค่อยมอบหมาย รายการที่ยังไม่มีข้อมูลต้องแสดงสถานะรอตรวจหรือไม่มีข้อมูล ห้ามเติมเลขหรือวันที่แทนต้นฉบับ

| ข้อมูล | เงื่อนไขบันทึก |
| --- | --- |
| ชื่อเรื่อง | จำเป็นเมื่อยืนยันลงรับ แยกชื่อเรื่องตามหนังสือกับชื่อเรียกสั้นได้ |
| ต้นทางและผู้ที่มีถึง | จำเป็นเมื่อยืนยันลงรับ เลือกหน่วยงานหรือบุคคล และบันทึกข้อความตามต้นฉบับได้ |
| ชนิดและเลขที่หนังสือ | เลือกชนิด เช่น บันทึก MN หนังสือภายในหรือภายนอกตามองค์กร เลขกรอกตามต้นฉบับ หรือเลือกไม่มีเลขหนังสือ |
| วันที่บนหนังสือ | กรอกเมื่อมี หากไม่มีให้ระบุไม่มีวันที่ แยกจากวันที่รับ |
| วันที่และเวลารับจริง | จำเป็น ใช้เวลาที่รับจริง ส่วนวันเวลาที่บันทึกระบบเก็บเพิ่มอัตโนมัติ |
| ช่องทางรับ | จำเป็น เช่น ระบบองค์กร อีเมล เอกสารกระดาษ หรือช่องทางอื่นที่กำหนด |
| เลขและลิงก์อ้างอิงระบบเดิม | กรอกเมื่อรับผ่านระบบเดิม เก็บรหัสรายการแยกจาก URL |
| ต้นฉบับและสิ่งที่ส่งมาด้วย | มีไฟล์หรือลิงก์ต้นฉบับ หากยังไม่ครบให้ระบุสิ่งที่ขาดและติดตามเพิ่ม |
| ความเร่งด่วนและการเข้าถึง | จำเป็น เลือกตามรายการที่องค์กรกำหนด เรื่องที่ยังไม่ประเมินสิทธิ์ให้เห็นเฉพาะผู้ตรวจรับ |
| ประเภทการดำเนินการ | กำหนดตอนคัดแยก เช่น เพื่อทราบ พิจารณา ดำเนินการ หรือตอบกลับ |
| เจ้าของเรื่องและงานย่อย | จำเป็นก่อนส่งงานที่ต้องดำเนินการ ผู้รับเพื่อทราบแยกจากผู้ทำงาน |
| กำหนดตอบภายนอก | กรอกตามหนังสือเมื่อมี เก็บแหล่งที่มาและการเปลี่ยนกำหนด |
| กำหนดส่งงานภายใน | จำเป็นก่อนมอบหมายงานที่ต้องดำเนินการ หากยังตั้งไม่ได้ให้ระบุเหตุผลและวันทบทวน |
| แฟ้มเรื่องและหมวดงาน | เลือกแฟ้มเดิมหรือสร้างใหม่ เรื่องที่กองเริ่มเองเปิดได้โดยไม่มีหนังสือรับ |
| บันทึกเพิ่มเติม | คำสั่ง รายละเอียดประสานงาน และรายการเอกสารที่ต้องติดตาม |

### พฤติกรรมของแบบฟอร์ม

บันทึกร่างได้ ใช้รายการหน่วยงานและบุคลากรเดิมช่วยเลือก ตรวจเตือนรายการคล้ายกันจากต้นทาง เลขหนังสือ และวันที่ แล้วให้ผู้ประสานงานตรวจยืนยัน กรณีเอกสารเพิ่มเติมของฉบับเดิมให้เชื่อมรายการเดิมแทนการรับซ้ำ

ปุ่มยืนยันลงรับเป็นจุดออกเลขทะเบียน การกดซ้ำหรือส่งคำขอซ้ำจากอินเทอร์เน็ตขัดข้องต้องได้รายการเดิม

## 4 หนังสือส่งและกติกาเลขทะเบียน

| ข้อมูลหนังสือส่ง | ข้อกำหนด |
| --- | --- |
| ที่มาและเจ้าของเรื่อง | เชื่อมแฟ้มงานและหนังสืออ้างถึงได้หลายฉบับ หรือเปิดเรื่องที่กองเริ่มเอง |
| ผู้รับและผู้เกี่ยวข้อง | ผู้รับหลัก สำเนา ผู้จัดทำ ผู้ตรวจ และผู้ลงนามจริงตามเอกสาร |
| ไฟล์เอกสาร | ร่างแต่ละรุ่น ฉบับส่งตรวจ ฉบับลงนาม และสิ่งที่ส่งมาด้วย |
| เลขทะเบียนส่งภายใน | ระบบออกตามจุดยืนยันลงทะเบียน แยกจากเลขหนังสือทางการ |
| เลขทางการและวันที่ | บันทึกจากระบบหรือหนังสือที่ได้รับการดำเนินการตามขั้นตอนองค์กร |
| หลักฐานการส่ง | วันที่ ช่องทาง ผู้ส่ง รายชื่อผู้รับ และไฟล์หรือรหัสรายการส่ง |
| ผลการส่งและตอบรับ | สำเร็จ ล้มเหลว รอตอบรับ ตอบรับแล้ว หรือไม่ติดตามการตอบรับ พร้อมหลักฐานเมื่อมี |

### แยกเลขตามหน้าที่

เก็บรหัสภายในฐานข้อมูล เลขบนหนังสือต้นทาง เลขอ้างอิงระบบองค์กร และเลขทะเบียนกองเป็นคนละช่อง รหัสภายในฐานข้อมูลไม่ต้องให้ผู้ใช้กรอก ส่วนเลขทางการให้บันทึกตามที่ได้รับจริง

| รายการ | กติกาที่ต้องพัฒนา |
| --- | --- |
| ชุดเลข | แยกตามกอง ประเภทรับหรือส่ง และรอบปี รูปแบบตัวอย่าง VD-IN-2569-0001 และ VD-OUT-2569-0001 |
| การออกเลข | ฝั่งเซิร์ฟเวอร์ออกเลขในธุรกรรมเดียวกับการลงทะเบียน และมีข้อบังคับเลขไม่ซ้ำในฐานข้อมูล |
| จุดตัดปี | ใช้วันลงทะเบียนและเขตเวลา Asia/Bangkok รอบปีและสิทธิ์ลงทะเบียนย้อนหลังต้องกำหนดก่อนเปิดจริง |
| ยกเลิกและแก้ไข | คงเลขเดิม ระบุเหตุผล ผู้ดำเนินการ และเวลา ไม่ลบเพื่อคืนเลขให้รายการอื่น |
| ส่งซ้ำและหลายผู้รับ | เก็บเป็นเหตุการณ์ส่งแยกครั้งต่อผู้รับ โดยไม่สร้างหนังสือหรือเลขทะเบียนใหม่โดยอัตโนมัติ |
| ปรับรูปแบบเลข | มีวันที่เริ่มใช้และประวัติ ห้ามเปลี่ยนเลขของรายการที่ลงทะเบียนแล้วตามค่าตั้งใหม่ |

ตัวอย่างเลขในหน้านี้ใช้แสดงรูปแบบภายในกอง การเปิดชุดเลขทางการต้องมีรหัสหน่วยงานและขอบเขตอำนาจที่กำหนดแล้ว

## 5 โครงสร้างข้อมูลและแนวทางระบบ

แยกข้อมูลหนังสือออกจากเรื่องงาน หนังสือหนึ่งฉบับอาจสร้างงานหลายงาน และเรื่องงานหนึ่งเรื่องอาจมีหนังสือรับ หนังสือส่ง และเอกสารประกอบหลายฉบับ ใช้ตารางเชื่อมเพื่อรองรับการอ้างอิงข้ามเรื่องโดยไม่ทำสำเนาหนังสือซ้ำ

| ข้อมูลหลัก | สิ่งที่จัดเก็บ |
| --- | --- |
| กองและสมาชิก | กองเจ้าของ สังกัดจริง บทบาท ช่วงเวลาสมาชิก และผู้รักษาการ |
| หนังสือ | รับหรือส่ง ชื่อเรื่อง เลขต้นทาง วันที่ ผู้เกี่ยวข้อง ระดับการเข้าถึง และแหล่งอ้างอิง |
| รายการทะเบียน | ชุดเลข ปี เลขลำดับ วันลงทะเบียน ผู้ลงทะเบียน และสถานะยกเลิก |
| เรื่องงานและเอกสารที่เกี่ยวข้อง | ชื่อเรื่อง เจ้าของเรื่อง สถานะ วันเป้าหมาย และความสัมพันธ์กับหนังสือแต่ละฉบับ |
| งานและการมอบหมาย | ผู้ทำงาน งานหลักหรืองานย่อย กำหนดเสร็จ ผลงาน และประวัติส่งตรวจ |
| ไฟล์และรุ่นเอกสาร | ตำแหน่งไฟล์ ชนิด ขนาด ผู้แนบ เวลา เลขรุ่น ค่าตรวจสอบ และบทบาทของไฟล์ |
| การส่งและการรับทราบ | ผู้รับแต่ละราย การส่งแต่ละครั้ง ผลการส่ง การตอบรับ และการรับทราบภายใน |
| สิทธิ์และเหตุการณ์ | สิทธิ์ดูหรือแก้ ผู้ให้สิทธิ์ การเปลี่ยนสถานะ ข้อมูลก่อนและหลังแก้ และเหตุผล |

### องค์ประกอบที่เสนอ

ใช้ฐานข้อมูลเชิงสัมพันธ์ ที่เก็บไฟล์แบบจำกัดสิทธิ์ และบริการฝั่งเซิร์ฟเวอร์สำหรับตรวจสิทธิ์ ออกเลข และเปลี่ยนสถานะ แยกพื้นที่พัฒนา ทดสอบ และใช้งานจริง เก็บการตั้งค่าหรือข้อมูลลับนอกชุดคำสั่งโปรแกรม

เริ่มจากการเชื่อมด้วยเลขอ้างอิงและลิงก์ การนำเข้าตารางให้มีหน้าตรวจข้อมูลและรายงานข้อผิดพลาด เมื่อทราบวิธีเชื่อมระบบเดิมจึงเพิ่มการรับข้อมูลอัตโนมัติ พร้อมรหัสป้องกันนำเข้าซ้ำและรายการเชื่อมไม่สำเร็จ

### ไฟล์และสิทธิ์

ไฟล์ดาวน์โหลดต้องตรวจสิทธิ์ทุกครั้ง รวมถึงลิงก์ตรงและหน้าตัวอย่าง ตรวจชนิดและขนาดไฟล์ เก็บไฟล์ที่ยังไม่ผ่านการตรวจแยกไว้ ฉบับที่นำไปส่งจริงต้องระบุรุ่นและเก็บหลักฐานเดิม เมื่อแก้ให้เพิ่มรุ่นแทนการทับไฟล์

การเห็นเรื่องงานไม่ได้ทำให้เห็นเอกสารทุกฉบับโดยอัตโนมัติ การเชื่อมหนังสือข้ามแฟ้มต้องไม่ขยายสิทธิ์ และผลค้นหา ตัวนับ รายงาน รวมถึงข้อความแจ้งเตือนต้องใช้ขอบเขตสิทธิ์เดียวกัน

## 6 สถานะและเงื่อนไขการทำงาน

ระบบต้องแยกสถานะของเรื่อง งาน และหนังสือส่ง เพื่อให้เห็นว่าเอกสารส่งออกแล้วแต่งานยังรอผลได้ ผู้ใช้เปลี่ยนสถานะผ่านคำสั่งที่มีเงื่อนไข ไม่เปิดให้เลือกสถานะปลายทางได้อย่างอิสระ

| ส่วน | ลำดับสถานะและทางแยก |
| --- | --- |
| เรื่องงาน | รอคัดแยก → ดำเนินการ → รอผลตอบกลับ หรือรอปิดเรื่อง → ปิดเรื่อง โดยส่งกลับดำเนินการหรือเปิดใหม่ได้เมื่อมีเหตุผล |
| งานที่มอบหมาย | รอรับงาน → กำลังทำ → ส่งตรวจ → เสร็จ หรือส่งกลับแก้ไข ผู้ตรวจต้องเป็นผู้ที่มีสิทธิ์และไม่ใช่ผู้ส่งงานชิ้นเดียวกัน |
| หนังสือส่ง | ร่าง → ส่งตรวจ → ผ่านการตรวจภายใน → รอดำเนินการทางการ → พร้อมส่ง → ส่งแล้ว หรือยกเลิก |
| เพื่อทราบ | ยังไม่รับทราบ → รับทราบ บันทึกเป็นรายคน โดยไม่เปลี่ยนงานที่ต้องทำให้เสร็จตามไปด้วย |
| การจัดส่ง | เก็บผลสำเร็จหรือล้มเหลวรายผู้รับ และสถานะตอบรับแยกจากการเปิดอ่านหรือรับทราบภายใน |

### เงื่อนไขที่ใช้ตรวจตอนพัฒนา

| เหตุการณ์ | กติกา |
| --- | --- |
| มอบหมายหรือเปลี่ยนคน | มีเจ้าของหลักหนึ่งคน ตรวจสมาชิกและสิทธิ์ เพิ่มสิทธิ์เท่าที่จำเป็น โอนงานพร้อมประวัติ |
| ส่งตรวจและแก้เอกสาร | ระบุผลงานรุ่นที่ส่งตรวจ การเพิ่มรุ่นหลังผ่านตรวจต้องส่งตรวจใหม่ก่อนนำรุ่นนั้นไปใช้ |
| เปลี่ยนกำหนด | เก็บกำหนดเดิม กำหนดใหม่ ผู้เปลี่ยน เหตุผล และแจ้งผู้รับผิดชอบ |
| พร้อมส่งหรือบันทึกส่งแล้ว | มีฉบับส่งจริง ผู้รับ และข้อมูลทางการตามที่กำหนด เมื่อบันทึกส่งแล้วต้องมีวัน ช่องทาง และหลักฐานการส่ง |
| ปิดเรื่อง | งานจำเป็นเสร็จหรือยกเลิกพร้อมเหตุผล มีผลดำเนินการ หากต้องตอบหนังสือต้องเชื่อมฉบับที่ส่งแล้ว |
| ยกเลิกหรือเปิดเรื่องใหม่ | จำกัดผู้มีสิทธิ์ ระบุเหตุผล และคงประวัติรวมถึงเลขทะเบียนทั้งหมด |

ฉบับที่ส่งแล้วแก้ทับไม่ได้ หากส่งผิดให้บันทึกเหตุการณ์แก้ไขหรือหนังสือฉบับใหม่ตามกระบวนการองค์กร การปิดเรื่องเพื่อทราบใช้เกณฑ์ผู้รับทราบที่จำเป็นตามที่เจ้าของระบบงานกำหนด

## 7 หน้าจอและการใช้งานรุ่นแรก

| หน้าจอ | สิ่งที่ผู้ใช้ต้องเห็นและทำได้ |
| --- | --- |
| ภาพรวมกอง | จำนวนเรื่องตามสถานะ งานเกินกำหนด เรื่องรอตรวจ และรายการใกล้ครบกำหนด กดตัวเลขไปดูรายการที่ตรงกันได้ |
| งานของฉัน | แยกต้องทำ ต้องตรวจ และเพื่อทราบ เรียงตามกำหนด กรองหมวดงาน และรับงานหรือเปิดรายละเอียดได้ |
| ทะเบียนรับ | ค้นและกรองหนังสือ ลงรับใหม่ ตรวจรายการคล้ายกัน ยืนยันออกเลข และส่งต่อคัดแยก |
| ทะเบียนส่ง | สร้างร่าง ส่งตรวจ แนบฉบับทางการ ยืนยันลงทะเบียน และบันทึกการส่งรายผู้รับ |
| รายละเอียดเรื่อง | เห็นเจ้าของ กำหนด ขั้นตอนปัจจุบัน งานย่อย หนังสือที่เกี่ยวข้อง และประวัติในหน้าเดียว |
| รายละเอียดหนังสือ | เห็นข้อมูลต้นฉบับ เลขทะเบียน รุ่นไฟล์ ผู้เกี่ยวข้อง แฟ้มที่อ้างอิง และเหตุการณ์รับส่ง |
| ค้นหาและทะเบียนย้อนหลัง | ค้นเลข เรื่อง ต้นทาง เจ้าของ หมวด ช่วงวันที่ และสถานะ ส่งออกเฉพาะรายการที่มีสิทธิ์ |
| ตั้งค่าและดูแลระบบ | สมาชิก บทบาท ผู้รักษาการ ชุดเลข หมวดงาน สิทธิ์ ประวัติ และสถานะงานสำรอง |

### แนวทางจัดหน้าจอ

ใช้รายการแบบตารางเป็นหลัก แสดงเลข เรื่อง ต้นทาง เจ้าของ กำหนด และสถานะโดยไม่ต้องเปิดหลายหน้า หน้ารายละเอียดใช้พื้นที่หลักดูเอกสาร และพื้นที่ประกอบสำหรับคำสั่งกับประวัติ บนมือถือให้เรียงข้อมูลสำคัญก่อนและกดดาวน์โหลดได้ตามสิทธิ์

แสดงปุ่มตามงานที่ผู้ใช้ทำได้ เช่น ลงรับ มอบหมาย ส่งตรวจ ส่งกลับ บันทึกส่ง และปิดเรื่อง ใช้ชื่อปุ่มให้ตรงผลของคำสั่ง แสดงข้อมูลที่ขาดเมื่อยังทำต่อไม่ได้ และเก็บข้อมูลที่กรอกไว้เมื่อบันทึกไม่สำเร็จ

### แจ้งเตือนและรายงาน

รุ่นแรกแจ้งเตือนในระบบเมื่อได้รับงาน ถูกส่งกลับ ต้องตรวจ หรือใกล้ครบกำหนด กดแล้วไปยังเรื่องที่มีสิทธิ์ดูได้ ข้อความแจ้งเตือนต้องไม่เปิดเผยรายละเอียดหนังสือที่ผู้รับไม่มีสิทธิ์ การส่งอีเมลหรือช่องทางอื่นพัฒนาหลังยืนยันช่องทางองค์กร

รายงานแยกจำนวนหนังสือ จำนวนเรื่อง และจำนวนงานย่อย แสดงเงื่อนไขที่ใช้คำนวณ ตัวเลขกับรายการเจาะดูต้องตรงกัน การส่งออกและเปิดเอกสารใช้สิทธิ์ชุดเดียวกับหน้าระบบ

## 8 ลำดับพัฒนาและจุดส่งมอบ

แบ่งเป็นรอบตามผลที่ตรวจได้ เริ่มรอบถัดไปเมื่อองค์ประกอบที่พึ่งพาผ่านการตรวจแล้ว ระยะเวลาแต่ละรอบให้ประเมินหลังทราบผู้พัฒนา โครงสร้างพื้นฐาน และปริมาณใช้งาน

| รอบ | งานและผลส่งมอบ | เกณฑ์ผ่านก่อนเดินต่อ |
| --- | --- | --- |
| 0<br>วางแบบ | ยืนยันฟอร์ม บทบาท ขั้นตอน เลขทะเบียน และรายการข้อมูล สร้างต้นแบบหน้ารับเรื่องกับหน้ารายละเอียด | ผู้ประสานงานและหัวหน้าลองเดินเรื่องตัวอย่างได้ครบ ยุติข้อขัดแย้งเรื่องอำนาจและการเข้าถึง |
| 1<br>รับและค้น | ฐานข้อมูล บัญชีและสิทธิ์ ทะเบียนรับ เลขอัตโนมัติ ไฟล์ ประวัติ และค้นทะเบียน | รับหลายคนพร้อมกันเลขไม่ซ้ำ เปิดไฟล์ตามสิทธิ์ได้ และค้นรายการที่เพิ่งรับเจอ |
| 2<br>มอบหมาย | เรื่องงาน งานย่อย งานของฉัน ส่งตรวจ ส่งกลับ เปลี่ยนคน กำหนด และแจ้งเตือนในระบบ | เรื่องที่มีหลายผู้ทำและการเปลี่ยนคนเดินต่อได้ ประวัติครบ ผู้ส่งงานตรวจงานตนเองไม่ได้ |
| 3<br>ส่งและติดตาม | ทะเบียนส่ง รุ่นเอกสาร ข้อมูลทางการ บันทึกส่งรายผู้รับ แฟ้มเรื่อง รายงาน และส่งออก | รับเรื่องแล้วตอบกลับจนปิดได้ รวมกรณีส่งล้มเหลวและรอผล ตัวเลขรายงานตรงทะเบียน |
| 4<br>ทดลองใช้ | ทดสอบผู้ใช้ แก้ข้อบกพร่อง สำรองและกู้คืน เตรียมข้อมูลตั้งต้น คู่มือ และแผนเปิดใช้ | เกณฑ์ตรวจรับผ่าน ไม่มีปัญหาสิทธิ์หรือข้อมูลสำคัญค้าง และระบุผู้ดูแลกับวิธีกลับไปทำงานเดิมได้ |

### ผู้ร่วมดำเนินการ

[เจ้าของระบบงาน] รับรองกระบวนงานและขอบเขต [ผู้ประสานงานกอง] เตรียมตัวอย่างและทดสอบทะเบียน [ผู้พัฒนา] ออกแบบและพัฒนาระบบ [ผู้ดูแลโครงสร้างพื้นฐานและข้อมูล] เตรียมพื้นที่ บัญชี สำรอง และดูแลหลังเปิดใช้ คนหนึ่งอาจทำหลายหน้าที่ได้ แต่ผลตรวจงานต้องมีผู้ใช้งานร่วมรับรอง

### วิธีควบคุมงาน

ใช้รายการงานในหน้าถัดไปเป็นฐาน ติดตามสถานะยังไม่เริ่ม กำลังทำ รอตรวจ และเสร็จ ทุกงานที่เสร็จต้องมีหลักฐานผลตรวจ เมื่อมีความต้องการเพิ่ม ให้ระบุผลต่อรอบพัฒนาและจัดลำดับก่อนนำเข้ารุ่นแรก

รุ่นต่อยอดเริ่มหลังนำร่องผ่าน โดยพิจารณาการเชื่อมระบบเดิม บัญชีองค์กร การลงนาม และการอ่านเอกสารช่วยกรอกจากภาระงานที่พบจริง

## 9 รายการงานพัฒนาส่วนรับและมอบหมาย

รายการด้านล่างเป็นงานที่ต้องมีสำหรับเปิดรุ่นแรก รหัสใช้ผูกกับงานพัฒนาและหลักฐานตรวจรับ งานในรอบเดียวกันเริ่มได้เมื่อรายการพึ่งพาพร้อม

| รหัส | รอบ | รายการงาน | เกณฑ์เสร็จ | พึ่งพา ED |
| --- | --- | --- | --- | --- |
| ED-01 | 0 | ยืนยันแบบและกติกา | มีแบบรับ ส่ง บทบาท และตัวอย่างกรณีครบ | เริ่มได้ |
| ED-02 | 0 | เตรียมพื้นที่และแบบข้อมูล | แยกทดสอบกับใช้งานจริง มีแบบข้อมูลและวิธีเปลี่ยนโครงสร้าง | 01 |

รหัสพึ่งพาแสดงลำดับขั้นต่ำ เช่น ED-19 ต้องอาศัยงาน ED-01 ถึง ED-18 ไม่ใช่ผลทดสอบที่ผ่านแล้ว สถานะเริ่มต้นของทุกรายการคือยังไม่เริ่ม

## 11 เกณฑ์ตรวจรับรุ่นแรก

ทดสอบด้วยผู้ใช้แยกบทบาทและข้อมูลที่เตรียมไว้ บันทึกผู้ตรวจ วันตรวจ ผลจริง และหลักฐานของแต่ละกรณี ผลที่คาดหวังในตารางนี้เป็นเกณฑ์รับงาน ยังไม่ใช่ผลการทดสอบระบบ

| กรณี | ผลที่ต้องตรวจพบ |
| --- | --- |
| U01 รับจนตอบจบ | รับหนังสือ มอบหมาย ตรวจ บันทึกส่ง และปิดเรื่อง ค้นเอกสารกับประวัติครบ |
| U02 เพื่อทราบ | รับทราบเป็นรายคน ไม่มีงานตอบกลับถูกสร้างโดยไม่จำเป็น |
| U03 หลายผู้ปฏิบัติ | เจ้าของรวบรวมหลายงานได้ งานย่อยเสร็จหนึ่งงานไม่ปิดทั้งเรื่อง |
| U04 เรื่องที่กองเริ่มเอง | เปิดเรื่องและร่างหนังสือส่งได้โดยไม่มีหนังสือรับ |
| U05 ส่งกลับและเปลี่ยนรุ่น | เก็บคำตรวจและรุ่นเดิม ฉบับแก้หลังผ่านตรวจต้องตรวจใหม่ |
| U06 เลขพร้อมกันและกดซ้ำ | คำขอพร้อมกันไม่ออกเลขซ้ำ คำขอเดิมที่ส่งซ้ำไม่สร้างทะเบียนเพิ่ม |
| U07 ปีและการยกเลิก | ทดสอบก่อนและหลังจุดตัดปี รวมย้อนหลังและยกเลิก เลขเดิมยังตามได้ |

### เงื่อนไขเปิดใช้งาน

กรณีที่เกี่ยวกับสิทธิ์ เลขทะเบียน การสูญหายของข้อมูล และการกู้คืนต้องผ่านทั้งหมด ปัญหาที่ทำให้รับหรือส่งเรื่องหลักไม่ได้ต้องแก้ก่อนเปิดใช้ รายการเล็กที่ยังค้างต้องระบุผลกระทบ ผู้รับผิดชอบ และกำหนดแก้ให้ผู้รับรองผลเห็นชอบ

กำหนดเป้าหมายเวลาตอบสนอง ปริมาณผู้ใช้พร้อมกัน ขนาดไฟล์ พื้นที่เก็บ ระยะข้อมูลสูญหายที่ยอมรับได้ และเวลากู้คืน ก่อนทดสอบสมรรถนะ ห้ามสรุปว่ารองรับได้จากการลองใช้เพียงคนเดียว

## 12 เตรียมเปิดใช้และงานที่ต้องเริ่ม

### เริ่มรอบ 0 ตามลำดับนี้

1 กำหนด [เจ้าของระบบงาน] และ [ผู้ประสานงานกอง] แล้วรวบรวมตัวอย่างหนังสือรับ ส่ง เพื่อทราบ และเรื่องหลายผู้ปฏิบัติ โดยใช้ข้อมูลปกปิดชื่อในพื้นที่พัฒนา

2 ยืนยันช่องข้อมูล ชุดเลข ผู้มอบหมาย ผู้ตรวจ และเกณฑ์ปิดเรื่อง พร้อมรายการระดับการเข้าถึงที่กองจะใช้

3 ให้ [ผู้ดูแลระบบเดิมและโครงสร้างพื้นฐาน] ระบุวิธีอ้างอิงข้อมูล พื้นที่ติดตั้ง บัญชีเข้าใช้ และข้อกำหนดเก็บเอกสาร

4 สร้างต้นแบบทะเบียนรับ หน้ารายละเอียดเรื่อง และงานของฉัน แล้วใช้กรณี U01 ถึง U05 เดินขั้นตอนก่อนเริ่มรอบ 1

### วิธีเปลี่ยนมาใช้งานและดูแลต่อ

เริ่มนำร่องด้วยกลุ่มผู้ใช้ที่กำหนด ตั้งวันเริ่มทะเบียนกองและนำเข้าเฉพาะเรื่องค้างที่จำเป็น กระทบยอดจำนวนรายการ เลขอ้างอิง และไฟล์ก่อนยืนยัน ทุกเรื่องต้องระบุว่าขั้นตอนใดบันทึกในระบบใด เพื่อลดการลงทะเบียนซ้ำ

ก่อนเปิดใช้ให้สำรองและลองกู้คืน ระบุผู้รับแจ้งปัญหาและผู้แก้ หากระบบขัดข้องให้เก็บรายการชั่วคราวตามวิธีที่ตกลง แล้วกระทบยอดเมื่อกลับมา ห้ามออกชุดเลขแข่งกันหลายช่องทาง ทบทวนงานค้างและปัญหากับผู้ใช้ระหว่างนำร่อง

ติดตามความครบถ้วนของเจ้าของงานและกำหนดส่ง ความถูกต้องของทะเบียน งานเกินกำหนด เหตุสิทธิ์ผิด และผลสำรองกู้คืน ใช้ผลนำร่องจัดลำดับงานต่อยอดและกำหนดรอบดูแลระบบ
