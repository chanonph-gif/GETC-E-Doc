# รอบ 0 วางแบบและเตรียมเริ่มพัฒนา

ติดตามใน [#1](https://github.com/chanonph-gif/GETC-E-Doc/issues/1)

เป้าหมายคือให้ผู้ประสานงานและหัวหน้าเดินเรื่องตัวอย่างผ่านแบบฟอร์มและต้นแบบ 3 หน้าหลักได้ ก่อนเริ่มลงทะเบียนจริง งานรอบนี้คือ ED-01 และ ED-02

## ลำดับงาน

- [ ] ระบุเจ้าของระบบงาน ผู้ประสานงาน ผู้ตรวจต้นแบบ และผู้ดูแลโครงสร้างพื้นฐาน
- [ ] รวบรวมรูปแบบเอกสารรับ ส่ง เพื่อทราบ และเรื่องหลายผู้ปฏิบัติ โดยปกปิดข้อมูลก่อนใช้พัฒนา
- [ ] กำหนดช่องบังคับ รายการชนิดหนังสือ ความเร่งด่วน การเข้าถึง และเกณฑ์ปิดเรื่อง
- [ ] กำหนดชุดเลขภายใน รอบปี จุดออกเลข และวิธีรับรายการย้อนหลัง
- [ ] กำหนดแบบข้อมูล กติกาสิทธิ์ และการเชื่อมเอกสารกับเรื่องงาน
- [x] ออกแบบต้นแบบ 3 หน้าด้านล่างและเดินกรณีตัวอย่าง
- [ ] กำหนดพื้นที่ติดตั้ง วิธีเข้าใช้ เทคโนโลยี และคำสั่งรัน จากข้อกำหนดองค์กร
- [ ] สรุปผลตรวจต้นแบบและข้อยุติลง Issues และ docs/decisions.md

## หน้าจอที่ทำก่อน

| หน้า | ข้อมูลและคำสั่งที่ต้องลองได้ |
| --- | --- |
| ทะเบียนรับ | เรื่อง ต้นทาง ชนิดและเลขหนังสือ วันที่รับ ช่องทาง แหล่งอ้างอิง ไฟล์ สิทธิ์ บันทึกร่าง ยืนยันลงรับ และเตือนรายการคล้าย |
| รายละเอียดเรื่อง | เจ้าของ กำหนด หนังสือที่เกี่ยวข้อง งานย่อย ผู้ตรวจ ผลงานรุ่นที่ส่งตรวจ ประวัติ และคำสั่งตามบทบาท |
| งานของฉัน | งานต้องทำ งานต้องตรวจ เพื่อทราบ กำหนดส่ง ตัวกรอง รับงาน ส่งผลงาน และรับทราบ |

## เรื่องตัวอย่างสำหรับเดินแบบ

ใช้ชื่อหน่วยงานและคนสมมติทั้งหมด เช่น หน่วยงานตัวอย่าง A ผู้ประสานงานตัวอย่าง และผู้ตรวจตัวอย่าง

1. ได้หนังสือขอข้อมูล มีผู้ปฏิบัติสองคน กำหนดตอบภายนอกกับส่งร่างภายในต่างกัน
2. ได้หนังสือเพื่อทราบ ส่งถึงสมาชิกหลายคนและเก็บการรับทราบแยกคน
3. กองเริ่มเรื่องเองและจัดทำหนังสือส่งโดยไม่มีหนังสือรับ
4. ผู้ตรวจส่งร่างกลับแก้ไข แล้วผู้จัดทำแนบรุ่นใหม่ส่งตรวจอีกครั้ง
5. เจ้าของเรื่องย้ายงาน ผู้รับผิดชอบใหม่ทำต่อได้และสิทธิ์เป็นไปตามการมอบหมาย

## เกณฑ์จบรอบ

- ผู้ใช้รู้ว่าตนต้องกรอกช่องใดและเรื่องอยู่กับใคร โดยไม่ต้องอาศัยผู้พัฒนาอธิบายทุกขั้น
- แยกเลขต้นทาง เลขรับระบบเดิม เลขกอง และเลขส่งทางการได้ชัดเจน
- เดินทางแยกเพื่อทราบ ต้องดำเนินการ ส่งกลับแก้ไข และเรื่องที่กองเริ่มเองได้
- ได้แบบข้อมูลและตารางสิทธิ์ที่นำไปทำ ED-03 ถึง ED-08 ต่อได้
- บันทึกวิธีติดตั้งและคำสั่งรันตามเทคโนโลยีที่เลือกจริง

ต้นแบบที่ใช้ข้อมูลสมมติถือเป็นหลักฐานตรวจแบบ การรับรองระบบใช้งานจริงให้ตรวจตาม [เกณฑ์ตรวจรับ](acceptance.md) หลังพัฒนา
