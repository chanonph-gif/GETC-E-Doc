# ต้นแบบรอบ 0

ใช้ทดลองขั้นตอนของ ED-01 และ ED-02 ด้วยข้อมูลสมมติ มีทะเบียนรับ รายละเอียดเรื่อง งานของฉัน และแฟ้มเรื่องที่กองเริ่มเอง

## เปิดและตรวจ

ใช้ Node.js 22 ขึ้นไป รันคำสั่งจากราก repository

```sh
npm run dev
npm run check
npm test
npm run build
```

ไม่มี dependency ที่ต้องติดตั้ง คำสั่ง dev เปิดที่พอร์ต 3000 หรือค่า PORT ที่กำหนด คำสั่ง build เตรียมไฟล์ static ใน dist/ ให้ใช้งานผ่านเว็บเซิร์ฟเวอร์ การเปิด index.html แบบ file:// ไม่รองรับ JavaScript modules และพื้นที่เก็บไฟล์ครบถ้วน

## วิธีทดลอง

1. เปิดทะเบียนรับ ค้นหรือกรองสถานะ กดตัวนับเพื่อดูรายการที่นำมาคำนวณ และส่งออก CSV ตามตัวกรอง
2. กดรับหนังสือ ระบุข้อมูลต้นทาง ไฟล์หรือลิงก์ต้นฉบับ หรือเอกสารที่รอติดตาม เลือกบันทึกร่างหรือยืนยันรับตัวอย่าง
3. เปิดรายละเอียดเรื่อง ใช้มุมมองนภาหรือธนามอบหมายเจ้าของเรื่อง กำหนดภายใน ผู้รับเพื่อทราบ และเพิ่มงานย่อย
4. เปลี่ยนมุมมองเป็นผู้รับผิดชอบ รับงาน แล้วส่งผลงานตรวจ ผลงานแต่ละรุ่นเก็บแยกกัน
5. ใช้มุมมองผู้ตรวจ ผ่านงานหรือส่งกลับพร้อมเหตุผล เมื่อผู้ปฏิบัติส่งรุ่นใหม่ต้องตรวจอีกครั้ง
6. หนังสือเพื่อทราบใช้การรับทราบรายคน ส่วนเรื่องที่ต้องตอบกลับมีแบบบันทึกการส่งตัวอย่างก่อนปิดเรื่อง
7. ลองเปลี่ยนผู้รับผิดชอบพร้อมเหตุผล เปิดเรื่องที่กองเริ่มเอง และดูประวัติเรื่อง

ปุ่มวิธีทดลองมีทางลัด 5 กรณี พร้อมเลือกมุมมองที่เกี่ยวข้องให้ การเริ่มชุดตัวอย่างใหม่จะล้างข้อมูลและไฟล์ที่ทดลองเพิ่มเฉพาะต้นแบบนี้

## ขอบเขตที่จำลอง

- ตัวอย่างเริ่มต้น 8 เรื่อง มีร่าง รอมอบหมาย งานกำลังทำ รอตรวจ เพื่อทราบ รอผล และปิดเรื่อง
- เลือกมุมมองผู้ประสานงาน หัวหน้า ผู้ปฏิบัติสองคน และผู้รับเพื่อทราบ
- ตรวจข้อมูลรับ เตือนรายการคล้าย ตรวจบทบาทจำลอง การรับงาน ส่งกลับ การส่งผลงานรุ่นใหม่ และเกณฑ์ปิดเรื่อง
- ไฟล์เก็บใน IndexedDB และข้อมูลเก็บใน localStorage ของ browser origin นี้ ล้างข้อมูลเว็บไซต์หรือเปลี่ยน origin แล้วข้อมูลอาจไม่อยู่
- การแจ้งเตือนแสดงเหตุการณ์ในข้อมูลตัวอย่าง ไม่มีการส่งอีเมลหรือข้อความออกไป

## ส่วนที่ต้องพัฒนาในระบบจริง

ต้นแบบไม่มี backend ยืนยันตัวตนหรือฐานข้อมูลร่วม การเลือกมุมมองและการกรองในเบราว์เซอร์ไม่ใช่ระบบรักษาความปลอดภัยสำหรับข้อมูลจริง เลข DEMO จำลองลำดับเท่านั้น ไม่ใช่บริการออกเลขพร้อมกันหลายผู้ใช้

ต้องทำการตรวจสิทธิ์ทุกคำขอ การออกเลขฝั่งเซิร์ฟเวอร์ในธุรกรรมเดียวกับการลงทะเบียน ข้อบังคับเลขไม่ซ้ำ การตรวจไฟล์ การสำรองกู้คืน อายุเก็บ และการเชื่อมระบบองค์กรตามแผนก่อนเปิดใช้จริง ห้ามนำเอกสารหรือบัญชีจริงมาใช้กับต้นแบบ

## โครงสร้าง

| ไฟล์ | หน้าที่ |
| --- | --- |
| app.mjs | แสดงหน้าจอ แบบฟอร์ม การนำทาง และการเลือกมุมมอง |
| domain.mjs | กติกาและการเปลี่ยนสถานะของข้อมูลจำลอง |
| fixtures.mjs | บุคคลและเรื่องสมมติ วันที่แสดงอ้างอิง Asia/Bangkok |
| storage.mjs | ข้อมูลและไฟล์ในเบราว์เซอร์ |
| domain.test.mjs | ตรวจแบบคำสั่งและกรณีขอบเขตด้วย Node test runner |
| styles.css | รูปแบบคอมพิวเตอร์ มือถือ และการเข้าถึงด้วยคีย์บอร์ด |
| assets | ฟอนต์ Sarabun และใบอนุญาต |

ผลตรวจต้นแบบต้องระบุขอบเขตแยกจากเกณฑ์ตรวจรับระบบจริง U01 ถึง U14 ไม่ทำเครื่องหมายเกณฑ์ตรวจรับจริงว่าผ่านเพียงเพราะต้นแบบผ่านทดสอบ
